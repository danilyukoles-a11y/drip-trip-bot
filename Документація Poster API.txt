Вступ
На платформі Poster ви можете створювати будь-які застосунки, наприклад:

Синхронізація замовлень і товарів між Poster і вашим сайтом. Використовуйте API онлайн-замовлень, щоб надсилати замовлення з сайту на касу. Касир в закладі обробить і прийме замовлення, а вся статистика буде доступна в Poster.
Спеціальні звіти в адмін-панелі. Якщо вам не вистачає можливостей Poster, ви можете створити застосунок, який вбудовується в адмін-панель і розширює її можливості. Не потрібно перемикатися між різними сайтами, все в одному місці.
Чат із співробітниками залу. Власник в адмін-панелі пише про оновлення системи мотивації, новини закладу. Повідомлення приходять на касу, кожен касир зможе ознайомитися з ним.
Можливості платформи
Робити запити до Web API. Отримуйте будь-які дані з акаунта в Poster, створюйте товари, тех. картки і робіть продажі.
Вбудовувати застосунок у POS-касі. Платформа дозволяє створювати утиліти для офіціантів і співробітників закладів.
Вбудовувати застосунок в адмін-панель. Розширюйте функціонал бек-офісу Poster, вбудувавши свій застосунок прямо в адмін-панель.
Інтегрувати ваші пристрої або створювати віртуальні. Таким чином ви зможете інтегрувати, наприклад, банківський термінал або створити віртуальний фіскальний принтер для роботи з фіскалізацією.
Початок роботи
Щоб адресувати API запити в конкретний акаунт, вам знадобиться токен доступу. Якщо ви пишете застосунок тільки для себе або знайомитеся з платформою, використовуйте токен Особиста інтеграція у вашому акаунті в розділі Доступ → Інтеграції.

Якщо ви розробляєте інтеграцію для клієнтів Poster, вам потрібно створити Застосунок в акаунті розробника. Від його імені ви будете працювати з системою і зможете опублікувати і продавати його в каталозі інтеграцій Poster.

Як створити застосунок
Щоб створити застосунок:

Зареєструйте акаунт розробника або увійдіть в існуючий.
На сторінці Poster for Developers → Створити застосунок заповніть назву, категорію і опис застосунку і натисніть Створити.
В розділі Розробка ваш акаунт розробника автоматично додасться в список тестуючих. Тестувальники бачать застосунок у каталозі до публікації.
application_id і application_secret ви знайдете в налаштуваннях застосунку, вони знадобляться для авторизації.

Акаунт розробника
Щоб почати розробляти свою інтеграцію:

Зареєструйте аккаунт розробника за посиланням https://dev.joinposter.com/signup.
Перейдіть у розділ Всі застосунки → Poster for Developers.
Натисність у правому верхньому кутку Новий застосунок.
Вкажіть назву застосунку в блоці Назва застосунку.
Коротко опишіть про застосунок в Короткий опис.
Оберіть категорію застосунку.
Натисніть Створити застосунок.
Після створення застосунку відкриваються розділи для редагування даних.

Налаштування
Application Id та Application Secret – ваші особисті дані для авторизації oAuth.

Категорії доступів – категорії доступу, які плануєте використовувати для свого застосунку.

oAuth – авторизація користувачів. При включені цього параметру додайте redirect_url.

Manage-платформа – включіть, якщо плануєте робити інтерфейс вашої інтеграції в адмін-панелі.

POS-платформа – включіть, якщо плануєте робити інтеграцію з касою.

Device-платформа – включіть, якщо плануєте підключати пристрої до вашої інтеграції.

URL для вебхуків – посилання для отримання вебхуків.

Отримувати вебхуки щодо – оберіть сутності, по яким плануєте отримувати вебхуки.

Сторінка підʼєднання – сторінка для підключення застосунку. Автоматично буде редіректити за цим посиланням з маркетплейсу, коли клієнт натискає Підключити. Використовуйте при oAuth–авторизації.

Опис
Опишіть застосунок та додайте логотип, щоб користувачам було легше зрозуміти для чого застосунок та знайти його в маркетплейсі.

Розробка
Сторінка для додавання акаунтів, в яких буде працювати застосунок без ревʼю. Можна використовувати для тестування або для роботи, якщо не плануєте публікувати застосунок в маркетплейсі. Після додавання акаунту в Розробники, у вказаному акаунті перейдіть у вкладку Застосунки → Усі застосунки та підключіть застосунок.

Публікація
Сторінка з переданням застосунка на ревʼю до наших спеціалістів. Перевіримо роботу програми та її вплив на Poster. Якщо є помилки або дії, які негативно впливають на програму – передамо зворотній звʼязок для виправлення.

Щоб прискорити процес модерації:

Протестуйте роботу застосунку перед подачею на ревʼю. Переконайтесь, що він працює у всіх необхідних сценаріях користувача.
Надайте тестові доступи до вашого сервісу або уточніть, що таких доступів нема.
Запишіть відео-інструкцію з процесом підключення та роботи інтеграції. Вона допоможе майбутнім користувачам легше ознайомитись з застосунком та підвищити залученість.
Напишіть список клієнтів Poster, які вже користуються застосунком.
Заповніть маркетинговий опис застосунку. Додайте інструкцію та ціни для кожного регіону.
Оплати
Список акаунтів та сплат за застосунок.

Підключення
Список акаунтів, які підключили застосунок.

Всі запити до Web API авторизуються за допомогою токена, який передається як GET-параметр. Виключеннями є лише запити на авторизацію.

Загальний формат адреси для всіх https-запитів
https://joinposter.com/api/{method}?format={format}&token={token}&param1=val1&param2=val2

Параметри адреси для всіх https-запитів
Параметр	Опис
method	Назва методу API, наприклад, clients.getGroups
token	Авторизаційний токен. Щоб отримати токен, пройдіть один зі способів авторизації
format	Формат запиту, доступні значення: json або xml
param1, val1	Додаткові параметри, які залежать від запиту
Відповідь надходить у вказаному форматі та містить обʼєкт верхнього рівня error або response. Обʼєкт error уточнюється параметрами code і message. Зі списком всіх помилок ознайомтесь таблиці помилок.

Авторизація в API
Для авторизації використовуйте протокол OAuth2. У результаті авторизації застосунок отримує access_token, з яким будете робити запити до API.

Крок 1
Перейдіть з застосунку на сайт Poster за адресою:

https://joinposter.com/api/auth?application_id={application_id}&redirect_uri={redirect_uri}&response_type=code

Якщо знаєте логін акаунту, використовуйте:

https://{account}.joinposter.com/api/auth?application_id={application_id}&redirect_uri={redirect_uri}&response_type=code

Параметр	Значення
application_id	ID застосунку в системі Poster, вказаний в налаштуваннях застосунку в акаунті розробника
redirect_uri	URL, на який користувача направляє після першого кроку авторизації. Має співпадати з тим, що в налаштуваннях застосунку в акаунті розробника.
response_type	Рядок з значенням code
Крок 2
Після переходу за однією з вказаних адрес, користувач авторизується та дає згоду на передачу даних акаунта. Доступи застосунку вказуються в налаштуваннях в акаунті розробника.

Після згоди на передачу даних, користувача буде перенапрвлено за адресою: redirect_uri?code=code&account=account

Параметр	Значення
code	32-символьний код, який використовується для ідентифікації застосунку на останньому кроці авторизації.
account	логін закладу в Poster, який необхідно використати для відправки всіх запитів до API Poster.
Крок 3
Останній етап авторизації — отримання access_token. Для цього застосунок має відправити POST-запит за адресою:https://{account}.joinposter.com/api/v2/auth/access_token.

Де account — це логін закладу в Poster, який передано в GET-параметрі під час зворотнього редіректу.

Тіло запиту відправляйте в форматі form-data

Приклад
PHP
<?php
$account = $_GET['account'];
$code = $_GET['code'];

$url = "https://$account.joinposter.com/api/v2/auth/access_token"; 

$auth = [
    'application_id'        => 76,
    'application_secret'    => '9642176a5cdfe3f65e6e00c27b668795',
    'grant_type'            => 'authorization_code',
    'redirect_uri'          => 'http://localhost:8080/',
    'code'                  => $code
];

$data = sendRequest($url, 'post', $auth);

Поширені запитання:
Загальне
1. Що таке акаунт розробника і для чого він потрібен?
Акаунт розробника — це спеціалізований акаунт у Poster, який містить у собі:

Тестове середовище: в акаунті доступні всі функції звичайного акаунта клієнта Poster.
Інструмент для створення вашого застосунку для подальшого його розміщення в маркетплейсі інтеграцій Poster.
Зареєструвати акаунт розробника ви можете, натиснувши Увійти праворуч угорі та обравши Немає акаунта?.

Акаунт розробника знадобиться вам тільки в тому випадку, якщо ви плануєте публікувати вашу інтеграцію в нашому маркетплейсі. Якщо ви розробляєте інтеграцію для себе або одного конкретного клієнта, наприклад, інтеграцію з особистим сайтом, вам достатньо використовувати токен особистої інтеграції з акаунта клієнта.

2. Чи потрібно платити за акаунт розробника?
Акаунт розробника безплатний. Після реєстрації акаунт автоматично буде продовжено на 15 днів. По закінченню цього терміну ви можете звернутися в наш чат підтримки з проханням продовжити ваш акаунт розробника, і наші менеджери з радістю вам допоможуть.

3. Як звʼязати акаунт розробника з акаунтом клієнта в Poster?
Повʼязувати акаунт розробника з акаунтом клієнта ніяк не потрібно. Акаунт розробника - це окремий акаунт, у якому ви налаштовуєте свою інтеграцію. Коли інтеграція готова, клієнт може під'єднати її до свого акаунта за прямим посиланням або через маркетплейс, якщо інтеграція опублікована там.

Важливо розуміти, що взаємодіють не акаунти, а застосунок розробника та акаунт клієнта через API-запити. Щоб ідентифікувати, до якого акаунту клієнта належить запит, використовується токен доступу.

4. Чи можна за допомогою API додати свій функціонал у Poster QR?
У Poster QR немає свого API, тому взаємодіяти з ним у вашій інтеграції не вийде. Але більшість налаштувань, пов'язаних з меню, ви можете зробити через Web API Poster.

Маркетплейс і публікація
5. Де можна знайти потрібну мені інтеграцію?
Інтеграції знаходяться в Каталозі застосунків Poster. Якщо ви не знайшли потрібну вам інтеграцію, ви можете найняти розробника, який допоможе вам додати необхідний функціонал, використовуючи наш відкритий API.

6. Чи можу я не публікувати застосунок у маркеті і дати до нього доступ тільки своїм клієнтам?
Так, ви можете не публікувати ваш застосунок у маркеті. У ваших клієнтів буде можливість підключити ваш застосунок за прямим посиланням https://joinposter.com/applications/Your-Integration-Name

7. Чи можу я продавати свою інтеграцію через Poster?
Опублікуйте вашу інтеграцію у нашому маркетплейсі, щоб продавати її клієнтам. Для цього пропишіть її опис, додайте фото, назву та надішліть її на рев'ю. Щоб пройти рев'ю, вам також знадобиться провести презентацію вашого застосунку нашому менеджеру.

Публікація вашої інтеграції в нашому маркетплейсі відкриває двері до нових ринків і допомагає генерувати нових лідів, адже наша система використовується в 23 тисячах локацій у 122 країнах світу. Білінг через нашу платформу спрощує процес продажів і гарантує вам стабільний дохід. Це дасть вам можливість розширити свою аудиторію і збільшити прибуток з Poster!

8. Скільки триває рев'ю інтеграції в маркетплейсі Poster?
Застосунок перевіряється до 14 днів. Якщо ви відправили вашу інтеграцію на повторне рев'ю, воно теж займе до 14 днів. Щоб прискорити процес модерації:

Протестуйте роботу застосунку перед його поданням на рев'ю. Переконайтеся, що він працює у всіх необхідних користувацьких сценаріях.
Надайте тестові доступи до вашого сервісу. Або уточніть, що тестових доступів у вас немає.
Запишіть відеоінструкцію з процесом підключення та роботи з інтеграцією. Вона допоможе майбутнім користувачам зорієнтуватися і підвищить їхню залученість.
Уточніть список клієнтів Poster, які вже тестують ваш застосунок.
Заповніть маркетинговий опис застосунку, додайте інструкцію для користувачів і ціни для кожного регіону.
9. Моя інтеграція вже опублікована в маркетплейсі Poster. Чи потрібно відправляти її на повторну модерацію, якщо я вніс(-ла) правки в POS-платформі або коді на сервері самого застосунку?
Ні. Для застосування змін у POS-платформі вашого застосунку потрібно лише виконати команду: npm run deploy.

10. Як швидко після деплою зміни з'являться у клієнта?
Зміни з'являться у клієнта після подвійного перезавантаження застосунку Poster.

11. Моя інтеграція вже опублікована в маркетплейсі Poster. Чи потрібно відправляти її на повторну модерацію, якщо я змінив(-ла) щось із перерахованого: маркетинговий опис, URL для вебхуків, URL для OAuth, URL для Manage, доступи до API?
Так, надішліть інтеграцію на повторне рев'ю, щоб ми перевірили нові дані та опублікували оновлення.

Авторизація та доступ
12. Де і як я можу отримати токен, якщо мені не потрібен окремий застосунок?
Зареєструйте акаунт у Poster, відкрийте адмін-панель і у вкладці Доступ → Інтеграції → Особиста інтеграція скопіюйте ключ.

Цей варіант підійде вам тільки в тому разі, якщо ви робите особисту інтеграцію для одного клієнта. Наприклад, інтеграцію з власним сайтом. У всіх інших випадках знадобиться налаштувати авторизацію oAuth для отримання токенів від різних клієнтів.

13. Як налаштувати OAuth-авторизацію?
Подивіться наш вебінар із відповіддю на це запитання. Також у нас є детальна інструкція в текстовому вигляді.

14. Скільки часу валідний токен?
Токен доступу випускається на 2 роки.

15. Що робити, якщо термін дії токена закінчився?
Клієнту необхідно перепідключити інтеграцію, щоб знову пройти авторизацію oAuth. Так ви отримаєте новий токен ще на 2 роки.

Токен особистої інтеграції можуть перевипустити працівники нашої підтримки. Для цього просто напишіть нам у чат.

Чи зручно нею користуватись?

Посилання на відео з демонструванням застосунку.
Тестові доступи до вашого продукта, якщо будуть необхідні для тестування.
Будь-яку додаткову інформацію, яка спростить процес ревʼю застосунку.
Переконайтесь що:

Заповнений опис для каталогу.
Інструкція містить GIF з описом підключення та роботи інтеграції.
Застосунок має доступ тільки до тих даних, які потрібні для роботи.
Код на вашому сервері працює в prod-режимі, відключено debug.
Буде плюсом, якщо хтось з існуючих клієнтів Poster вдало працює з застосунком.
Працівники Poster перевірять, що інтеграція працює стабільно та не псує дані клієнтів і після цього дадуть вам відповідь.

Гайдлайни
Застосунки на касі
Застосунок в Poster використовується працівниками залу на пристроях з touch-дисплеями. У роботі закладу дуже важлива швидкість роботи. Чим швидше офіціант взаємодіє з касовим рішенням, тим більше часу він зможе приділити спілкуванню з гостем. З цього слідує декілька правил при розробці застосунку для Poster:

Великі елементи інтерфейсу. Офіціант працює з застосунком швидко, він не має довго цілитись в кнопку. Рекомендуємо не робити елементи інтерфейсу, клікабельна область яких менше 44×44 пікселя.
Прості сценарії взаємодії. Спрощуйте логіку застосунку, зменшуйте кількість дій, які має зробити користувач, щоб отримати результат.
Швидка робота та зворотній звʼязок. Застосунок не має «зависати», в будь-який момент користувач має розуміти, що відбувається.
Невеликий розмір bundle. Намагайтесь економно додавати сторонні бібліотеки, щоб ваш bundle-файл не розростався. Великий bundle впливає на швидкість запуску застосунку, особливо в закладах з повільним інтернетом.

<?php

$client_secret = 'fe2bc8e865d8fc2236968ee53c3b2bd5';

$verify_original = $postData['verify'];

    $postData['account'],
    $postData['object'],
    $postData['object_id'],
    $postData['action'],
];

// Якщо є додаткові параметри
if (isset($postData['data'])) {
    $verify[] = $postData['data'];
}
$verify[] = $postData['time'];
$verify[] = $client_secret;

// Створюємо рядок для верифікації запиту клієнтом
$verify = md5(implode(';', $verify));

// Перевіряємо валідність даних 
if ($verify != $verify_original) {

}

// Якщо не відповісти на запит, Poster продовжить слати Webhook

POS Platform: Вступ
Платформа на касі (POS Platform) — це технологія, яка дозволяє стороннім розробникам розширювати функціональність касового рішення Poster. Використовуйте платформу на касі для застосунків, з якими взаємодіє офіціант або касир. Наприклад:

Інтеграція зовнішніх систем лояльності з Poster. Касир авторизує гостя за номером телефону або QR-кодом, пропонує йому списати бонуси.
Інтеграції IP-телефонії та АТС з Poster. Касир приймає вхідний дзвінок і моментально бачить картку клієнта на касі — його ім'я, адресу, недавні покупки.
Чат з працівниками залу. Власник в адмін-панелі пише про оновлення системи мотивації, новини закладу. Повідомлення приходять на касу, кожен касир повинен ознайомитися з ним.
Технології
У Poster гібридна архітектура, основна частина бізнес-логіки застосунку написана з використанням веб-технологій. Застосунок на платформі для каси виконується на JavaScript. Ви можете писати застосунок на будь-якій мові, яка компілюється в JS (CoffeeScript, TypeScript). Застосунок завантажується в систему у вигляді одного JS-файлу (bundle).

Усі ресурси, які використовує застосунок (css, зображення, шрифти, звуки), повинні бути включені в bundle. Для цього потрібно використовувати збірники. У прикладах, які ви знайдете в документації, використовується збірник webpack.

JS-файл з застосунком запускається всередині спеціального контейнера на касі. Контейнер представляє собою iFrame з вбудованими методами, за допомогою яких застосунок спілкується з Poster. Застосунок у контейнері кешується на касі і може запускатися та працювати без з'єднання з інтернетом.

Для створення інтерфейсу застосунку, ви можете використовувати будь-який фреймворк або бібліотеки. Наприклад, Backbone, VueJS, Angular, React. Касовий інтерфейс Poster написаний на React, тому якщо ви пишете застосунок за допомогою React, ви зможете використовувати деякі готові компоненти, які звичні для користувачів Poster. При роботі з іншими фреймворками, усі компоненти вам доведеться реалізувати самостійно або встановлювати сторонні модулі.

Методи
Вашому застосунку доступний глобальний об'єкт Poster. Об'єкт містить набір методів для підписки на події, роботи з колекціями даних та інтерфейсами в Poster.

# Telegram Bot Crawler — Design Spec

> Інструмент для автоматизованого реверс-інжинірингу Telegram-бота конкурента `@Vape_Rivne_Bot`.
> Збирає повну структуру навігації, тексти, кнопки, callback_data, медіа-мітки.

## 1. Мета

Автоматично зібрати повне дерево навігації бота-конкурента, щоб не проходити вручну кожен екран. Результат — JSON + Markdown, які стануть основою для проєктування власного бота.

## 2. Технічний стек

| Компонент | Технологія |
|---|---|
| Мова | Python |
| Telegram клієнт | Telethon |
| Конфігурація | python-dotenv |
| Вивід | JSON + Markdown |

## 4. Архітектура

### 4.1. Загальний потік

1. Авторизація Telethon (інтерактивна, один раз)
2. Відправка `/start` боту
3. Рекурсивний обхід дерева кнопок
4. Збереження результатів у JSON + Markdown

### 4.2. Стратегія навігації

- **Inline-кнопки (callback_data):** натискаємо напряму — вони stateless, не потребують "Назад"
- **Reply-кнопки:** перед кожною новою гілкою відправляємо `/start` для повернення у початковий стан. Якщо бот не реагує на `/start` (не повертає очікувану reply-клавіатуру) — пробуємо `/menu`, потім текст `"Меню"`. Якщо нічого не спрацювало — помічаємо гілку `[RESET_FAILED]` і переходимо до наступної
- **Навігаційні кнопки** ("Назад", "Головне меню", "◀️", "⬅️"): записуємо в результат, але НЕ натискаємо

### 4.3. Рекурсивний обхід

Для кожного екрану:
1. Зчитати текст повідомлення бота
2. Зібрати reply-клавіатуру (якщо є)
3. Зібрати inline-клавіатуру (якщо є)
4. Для кожної кнопки:
   - Перевірити чи це навігаційна кнопка → skip
   - Перевірити по блеклисту (unsafe) → записати але не натискати
   - Перевірити на дублікат (вже відвіданий екран) → skip
   - Натиснути і рекурсивно обробити відповідь

### 4.4. Дедуплікація

Кожен екран ідентифікується **хешем від набору кнопок** (тексти кнопок + callback_data, без тексту повідомлення). Текст повідомлення не включається в хеш, бо може містити динамічний контент (кількість товарів у кошику, часові мітки тощо). Якщо хеш вже зустрічався — вузол позначається як посилання на існуючий, без повторного обходу.

### 4.5. Обмеження глибини

`MAX_DEPTH = 6` застосовується **до кожної гілки окремо**. При досягненні ліміту поточна гілка зупиняється з міткою `[MAX_DEPTH]`, але обхід інших гілок продовжується.

### 4.6. Обробка FloodWaitError

Якщо Telegram повертає `FloodWaitError` — скрипт автоматично чекає вказану в помилці кількість секунд + 5 секунд запасу, і продовжує роботу.

### 4.7. Telethon-сесія

Файл сесії (`crawler_session.session`) зберігається в `crawler/`. Додається в `.gitignore`.

## 5. Безпечний режим

### 5.1. Блеклист (unsafe — НЕ натискаємо)

| Патерн | Причина |
|---|---|
| `*замовлен*`, `*оформ*`, `*підтверд*` | Створення замовлення |
| `*оплат*`, `*сплат*`, `*liqpay*`, `*pay*` | Ініціація платежу |
| `Request Contact` (тип кнопки) | Відправка номера телефону |
| `Request Location` (тип кнопки) | Відправка геолокації |
| `*видалити все*`, `*очистити*` | Деструктивні дії |

Перевірка case-insensitive, українська + англійська.

### 5.2. Навігаційні патерни (записуємо, НЕ натискаємо)

`назад`, `back`, `◀️`, `⬅️`, `головне меню`, `на початок`, `меню`, `↩️`

### 5.3. URL-кнопки

Inline-кнопки з типом `url` — зберігаємо URL, не переходимо.

### 5.4. Switch inline query

Зберігаємо параметри, не виконуємо.

## 6. Обробка крайніх випадків

| Ситуація | Рішення |
|---|---|
| Пагінація ("▶️", "Далі", "1/5") | Натискаємо і збираємо всі сторінки, зупиняємось коли callback_data наступної кнопки повторюється або набір кнопок (хеш) збігається з уже відвіданим |
| Таймаут відповіді бота | 10 секунд, 2 ретраї, потім skip з міткою `[TIMEOUT]` |
| Бот надсилає кілька повідомлень | Чекаємо 2 секунди після останнього, збираємо всі як один екран |
| Медіа (фото, відео, документ) | Записуємо тип + caption, файл не завантажуємо |
| Дублікат екрану | Посилання на існуючий вузол |

## 8. Формат виводу

### 8.1. JSON (bot_structure.json)

Дерево вузлів. Кожен вузол:

```json
{
  "trigger": {
    "type": "inline|reply|command",
    "text": "Текст кнопки",
    "callback_data": "cat_1"
  },
  "text": "Текст відповіді бота",
  "media": {"type": "photo", "caption": "..."} | null,
  "reply_keyboard": ["Кнопка 1", "Кнопка 2"],
  "inline_keyboard": [
    {"text": "Кнопка", "callback_data": "cb_1", "url": null}
  ],
  "skipped": false,
  "skip_reason": null,
  "children": []
}
```

Кореневий обʼєкт містить метадані: `bot`, `crawled_at`, `total_screens`, `total_buttons`, `skipped_unsafe`, `max_depth_reached`.

### 8.2. Markdown (bot_structure.md)

- Заголовок зі статистикою
- Дерево навігації з хлібними крихтами (`/start → Каталог → POD-системи`)
- Callback_data в квадратних дужках `[cat_1]`
- Таблиця пропущених unsafe-кнопок в кінці

## 9. Запуск

```bash

python crawler/crawler.py

```

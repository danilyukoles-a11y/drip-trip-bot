# DEV_P_13 — Telegram-бот для вейп-магазину

## Опис проєкту

Telegram-бот каталог для офлайн+онлайн вейп-магазину. Референс — бот конкурента @Vape_Rivne_Bot (Taste_bot). Інтеграція з CRM Poster. Замовник — Діма.

## Стек

Python, aiogram 3.x, Supabase, Poster API, VPS
Бот: @drip_trip_shop_bot
Poster акаунт: drip-trip

## Прогрес

### Сесія 2026-04-03 / 2026-04-07

### Сесія 2026-04-08 / 2026-04-09

- **Фаза 2 завершена**: структура проєкту `vape_bot/`, config/settings.py з хардкодженими категоріями, схема БД (users, cart_items, orders) створена в Supabase, database CRUD модулі.

- **Poster API**: URL = `https://drip-trip.joinposter.com/api/`, дворівневі категорії (4 кореневих → підкатегорії-бренди).
- **Виявлено**: 70 товарів з ціною 0 — це батьківські товари з модифікаціями (варіанти кольорів/смаків). Тимчасовий фільтр price > 0. Підтримка модифікацій відкладена.
- **Замовник задоволений** MVP, планує переструктурувати категорії в Poster та дати новий токен з правами складу.
- Наступний крок: чекаємо від Дмитра новий токен → підключаємо залишки та модифікації.

### Сесія 2026-04-11

- **Залишки працюють** з наявним токеном через `storage.getStorageLeftovers` — новий токен НЕ потрібен (раніше використовували неіснуючий метод).
- **Модифікації реалізовані**: 70 батьківських товарів з варіантами (кольори/смаки) тепер показуються з діапазоном цін, вибір модифікації → одразу в кошик.
- **Наявність**: реальні залишки зі складу, товарів без стоку позначені ❌.
- **Кеш оптимізовано**: pre-load при старті + фоновий рефреш через asyncio.to_thread.
- **Фідбек замовника**: 18+ перевірка, навігація "назад" на правильну сторінку, breadcrumb дерево категорій.
- **Firecrawl MCP** встановлено для майбутнього краулу документації.
- Наступний крок: чекаємо фідбек Дмитра, потім — notification channel, адмін-команда, оновлення категорій.

### Сесія 2026-04-14 / 2026-04-16

- **Фільтр наявності**: товари без стоку приховані, в наявності — з `✅` префіксом.
- **Poster orders integration**: кожне замовлення з бота → `incomingOrders.createIncomingOrder`, автоматично створюється `transaction_id` (чек) і клієнт в CRM. Дмитро отримує email + push від Poster, бачить замовлення на касовому ПК.
- **Retry**: 3 спроби (1/2/4с) через `httpx.AsyncClient`, при фейлі друге повідомлення в канал.
- **Нормалізація телефонів**: всі формати (`0XX`, `380XX`, `+380XX`, з пробілами/дужками) → `+380XXXXXXXXX`.
- **Адмін-команда `/cleanup_test_orders`**: чистить Supabase за `TEST_PHONE`, Poster не чіпає (Дмитро просив сам закривати чеки вручну).
- **Deps pinned**: aiogram 3.27, supabase 2.28.3, httpx 0.28.1. `requests` залишено як транзитивна залежність (`supabase → storage3 → pyiceberg`), наш код на httpx.
- **Важливо про Poster API**: 
  - Token МАЄ бути в URL params, НЕ в body
  - Body має бути JSON (Content-Type: application/json)
  - Phone валідується Poster'ом — `+380000000000` не проходить
  - НЕ існує API для видалення incoming_order, тільки касир вручну
  - `transactions.removeTransaction` робить soft-delete (статус "Видалений")
- **Схема Supabase**: у `orders` додано `poster_order_id`, `poster_transaction_id`.
- **Фідбек замовника**: Дмитро каже "90% готовності, готовий запускатись у прод".
- Наступний крок: deployment (сервер ~500грн/міс, Олесь знає як сам), потім структурування категорій у Poster від Дмитра.
